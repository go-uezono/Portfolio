ezChef Recipe Platform

Problem and Motivation

Take out apps made eating out the default, but that is expensive. Cooking at home is cheaper, builds useful skills, and can be social - yet many people still do not cook because they cannot decide what to make, or they do not have easily accessible recipes in one place.

ezChef is the recipe layer for that gap: search, save, and share recipes so home cooking is easier to choose.

Key Features

  1. Users can quickly find recipes based on one on more queries
  2. Users have a "cookbook" where they can add and save recipes to for easy referral
  3. Users can create, share, and review recipes
  4. Users will also be able to see the nutritional value of each recipe

Tech Stack

Layer Technologies
Frontend React, React Router, Material UI, Emotion, Webpack + Babel
Backend + Database Django, Django REST Framework; MySQL
Authentication JWT Authenticaion
Tooling Python venv + pip; Node for npm run dev/build; Local run: python manage.py runserver

My Contributions

  • Proposed ezChef and acted as project lead.
  • Designed and finalized the EER and relational models (normalized ingredients/quantities/units, reviews, cookbooks).
  • Wrote the MySQL DDL, loaded sample data, and stood up the live schema.
  • Implemented most of the Django REST backend: unmanaged models mapped to the schema, serializers, and views (auth, recipes, categories,cookbook-related endpoints).
  • Helped wire the React UI to those APIs and debug schema/JWT/URL mismatches when the frontend and database disagreed.

    • Challenges and Solutions

    This is was my first fullstack app in a heavy database class, so the schema had to be right before the product could exist.
    The main difficulties were:

  • Schema-first Django - tables already existed from our DDL. We could not let migrations invent a whole new schema; unmanaged models, serializers, and views had to stay 1:1 with MySQL or the UI would return empty/wrong data.
  • Auth and a split stack - JWT on Django, then React calling /api/..., including CSRF and token refresh so more than one user could use the app locally.
  • Frontend-backend contract - cookbook membership, recipe ingredients (amount + unit), and category type/region only worked after the API shape matched the relational design. I learned Django, REST, and enough React/JS on the job to close those gaps.

    • Future Implementations

  • Deploy the app so it is not local-only.
  • Allow users to add recipe photos, with a small cap (e.g. instructional images) so pages stay scannable.
  • In-app discussion thread on recipes, realtime chat as a later system.
